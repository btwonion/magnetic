# Minecraft 1.21.1 Fabric and NeoForge Targets Design

## Goal

Add Minecraft 1.21.1 as a paired Fabric and NeoForge target while preserving the existing 26.1.2 and 26.2 targets. Both new production jars must compile from the shared mod sources, contain the same generated gameplay data, use Java 21 bytecode, and use the packaging/mapping pipeline required by their loader.

## Target Matrix

Register two Stonecutter nodes:

| Node | Minecraft | Platform | Production jar | Java |
| --- | --- | --- | --- | --- |
| `1.21.1-fabric` | `1.21.1` | `fabric-loom-remap` | Loom `remapJar` | 21 |
| `1.21.1-neoforge` | `1.21.1` | `moddevgradle` | ModDevGradle `jar` | 21 |

The 26.x Fabric nodes remain on `fabric-loom`, where no remapping is required, and retain Java 25. ModStitch's `javaVersion` and `finalJarTask` abstractions remain the single source of truth for JVM targets and publishable artifacts.

The target property files use these dependencies:

- Fabric API `0.116.14+1.21.1`
- Mod Menu `11.0.3`
- NeoForge `21.1.238`
- YACL `3.8.1+1.21.1-fabric` and `3.8.1+1.21.1-neoforge`
- KotlinLangForge loader generation `3.1`, producing `2.11.2-k2.3.10-3.1+neoforge` through the existing dependency convention

Both nodes advertise Minecraft `1.21.1` only. The Fabric node sets `vers.mcVersionRange=1.21.1`; the NeoForge node sets `vers.mcVersionRange=[1.21.1]`.

## Build Architecture

Keep the current shared `mod/build.gradle.kts`. Loader detection must continue to classify both `fabric-loom` variants as Fabric and `moddevgradle` as NeoForge. The build must not introduce Architectury Loom, a separate legacy module, or Forge support.

The Fabric 1.21.1 node must select `fabric-loom-remap`. Minecraft 1.21.1 is an obfuscated release, so the named development output is not the distributable artifact. `modstitch.finalJarTask` must resolve to `remapJar` for publishing and verification.

The NeoForge node remains on regular ModDevGradle. No Forge-only `moddevgradle-legacy`, `mods.toml`, or `reobfJar` configuration is added.

## Shared Source Compatibility

Use narrow Stonecutter version conditions around APIs that differ between 1.21.1 and 26.x. Loader-only behavior remains controlled by the existing `fabric` and `neoforge` constants. Conditions should prefer semantic version checks over target-name checks so future versions can reuse the correct side.

Expected compatibility boundaries include:

- Minecraft resource identifiers (`ResourceLocation` in 1.21.1 versus `Identifier` in 26.x).
- Registry bootstrap hooks (`RegistryDataLoader`-era behavior in 1.21.1 versus `RegistryLoadTask` in 26.x).
- Permission checks and command APIs introduced or moved after 1.21.1.
- Enchantment registry/data builder signatures.
- NeoForge loader lifecycle, config-screen registration, command events, and tick events.
- Minecraft method descriptors used by mixins, including bucket placement and entity/drop hooks.

Shared gameplay behavior and configuration format must not diverge. Compatibility branches may adapt types, event registration, and method descriptors, but must feed the same existing loader-neutral logic.

## Metadata and Dependencies

The existing Fabric and NeoForge templates remain authoritative. Each 1.21.1 property file provides the loader-specific Minecraft version syntax and dependency coordinates expected by its template.

Both targets continue to require YACL. Fabric continues to require Fabric API and Fabric Language Kotlin and optionally integrates Mod Menu. NeoForge continues to require KotlinLangForge. Publication metadata must identify the correct loader and must point to `modstitch.finalJarTask`.

## Generated Data

Fabric remains the canonical data generator. Add `mod/generated/1.21.1` and generate it through `:mod:1.21.1-fabric:runDatagen`. The matching NeoForge target packages that same directory through the existing `processResources` configuration.

The generated directory must include the Magnetic enchantment definition and the `auto_move`, `in_enchanting_table`, `tradeable`, and `treasure` enchantment tags. Fabric and NeoForge jars must contain byte-identical copies of these generated JSON resources.

## Validation

Implementation is complete only when all of the following pass:

1. Stonecutter generates compilable sources for both 1.21.1 nodes.
2. `:mod:1.21.1-fabric:build` succeeds and its production jar is the remapped jar.
3. `:mod:1.21.1-neoforge:build` succeeds and its production jar is the ModDevGradle jar.
4. New class files have Java class-file major version 65, while the existing 26.x targets retain their current Java 25 configuration.
5. Each jar contains the correct loader manifest, mixin metadata/refmap, access widener or transformed access configuration, embedded Kotlin/config libraries, and generated data.
6. The Fabric and NeoForge manifests declare Minecraft 1.21.1 and their loader-specific dependencies correctly.
7. The generated data packaged in the two jars is identical.
8. The repository's root `build` task succeeds across the complete target matrix and Paper project.

## Non-Goals

- Adding Minecraft Forge support.
- Adding other Minecraft 1.21.x targets.
- Changing the latest release aggregation, which intentionally releases only the current 26.2 mod targets and Paper.
- Refactoring loader-neutral gameplay behavior unrelated to compatibility.
